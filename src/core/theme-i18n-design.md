# 主题与国际化

## 定位

Cell 与 Box 仅描述页面的**结构与内容**——布局层次、数据、事件、插槽关系。它们不关心"用什么颜色"、"播放什么动画"、"显示什么文本"。

主题系统与 i18n 系统是与之平行的两个横切资源系统：
- **主题系统**回答"如何呈现"
- **i18n 系统**回答"用什么文本"

三者通过**资源引用**与**注入机制**解耦：Cell 引用资源标识，系统在渲染时注入具体值。主题与语言可独立切换，切换只触发呈现刷新，不影响 Cell 结构与数据。

## 设计原则

- **资源标识即契约**：Cell 引用的是稳定的资源标识（如 token、i18n key），不随主题或语言变化
- **声明优先**：Cell 声明"需要什么"（如需要玻璃折射背景），由主题系统决定"如何实现"
- **可降级**：动态属性依赖运行时能力，系统检测能力并选择可用实现，不可用时回退
- **可组合**：主题包与语言包可叠加扩展，不强制单文件全量定义
- **响应式**：资源切换通知订阅方重新呈现，过程对 Cell 透明

## 资源引用模型

Cell 不硬编码任何呈现值或文本，全部通过资源标识引用：

- 主题 token：命名一个主题资源，如颜色、字号、动画时长、效果参数
- i18n key：命名一条文本资源

资源标识是 Cell 与主题/i18n 之间唯一的耦合点。标识稳定，则 Cell 不受主题演进与语言增减影响。

## 主题系统

主题是一组呈现资源的集合，分为两层。

### 静态资源层

静态资源是确定性的、可预编译的呈现值，与运行时环境无关。

- **颜色**：调色板与语义色（primary、danger、背景、前景、边框、状态色等）
- **字体**：字体族、字号、字重、行高
- **图标**：图标集
- **组件静态样式**：组件基础外观规则

### 动态属性层

动态属性依赖运行时环境，或涉及连续变化的呈现。按承载方式分两类：

**参数型**——以值描述，注入到 Cell 组件即可生效，不需要额外渲染表面：
- 动画：过渡曲线、时长、关键帧
- CSS 可达的效果：阴影、模糊、发光等

**合成型**——需要独立渲染表面与计算管线，超出单组件 DOM 参数范畴：
- 示例：WebGL 玻璃折射、粒子系统、光影、自定义着色器合成
- 拥有独立渲染表面，与 DOM 层叠呈现
- 可捕获目标区域的 DOM 或几何作为输入
- 有自己的渲染循环与资源管理
- 多个特效可共享同一合成表面以优化性能

两类均以**声明式描述**表达（效果类型与参数），由渲染层根据运行时能力解析为具体实现。声明式描述使效果可在不同环境间移植，并为降级与替换预留空间。合成型特效的承载机制见下节[特效合成](#特效合成)。

### 特效合成

承载合成型特效的机制。与主题系统解耦：主题描述"要什么特效"，特效渲染器决定"如何渲染"。

- **合成表面**：独立渲染层，与 DOM 层叠，可服务于多个 Cell 的多个特效。一个合成表面可承载 WebGL canvas、Canvas2D、SVG filter 等不同实现载体
- **特效实例**：一个特效描述的具体运行实例，关联目标 Cell 与合成表面
- **输入源**：特效可声明输入源（如目标 Cell 的渲染结果、几何边界、滚动位置），合成层负责采集与提供
- **渲染时序**：合成层的渲染循环与 React DOM 渲染协调，避免时序冲突与重复绘制
- **生命周期**：特效实例随目标 Cell 的挂载/卸载创建与销毁，释放渲染资源；合成表面的存续独立于单个特效
- **实现路径选择**：特效渲染器根据描述与运行时能力选择实现（WebGL / Canvas2D / CSS filter / 降级），同一特效描述在不同环境下可有不同实现路径

合成型特效不进入 Cell 的 Box 布局层级——它叠加在 Box 渲染结果之上，以独立层的方式参与最终呈现。Cell 仅声明"此处需要某特效"，不参与特效的内部计算与渲染管理。

### 尺寸变化特效（Resize Effects）

已实现的动态属性特例：视口（页面 `viewport()` 与浮动视口 `floatingViewport()`）尺寸变化时呈现的特效，由主题以声明式描述驱动，与"合成型特效"同属动态属性层。

- **声明式 API**：主题包在 `effects.resize` 中声明 `{ type, ...params }`，如 `{ type: 'stretch' }`、`{ type: 'blur', blur: 10 }`。type 是特效契约，params 的语义由对应实现定义
- **注册表解析**：渲染层按 type 从特效注册表（resize-effects）解析实现组件；未识别类型返回 null，降级为无特效，保证主题演进不影响渲染层
- **实现自由**：每个特效实现是一个 React 组件，接收统一契约 `{ builder, spec, children }`（children 为视口三层渲染），内部可用任意技术（transform、CSS filter、WAAPI、canvas 等）。已实现（三者共用"拉伸缩放四角对齐"的投影呈现，差异仅在真实布局的追赶时机）：
  - `stretch` 拉伸：投影 + 实时追赶——尺寸变化瞬间内容以 transform scale 整体投影到新尺寸（四角实时对齐窗口，画面连续不撕裂）；不冻结，真实布局实时计算，reflow 就绪（下一帧）立即把当前屏上的拉伸原子替换为新布局（无 settleDelay 防抖）
  - `blur` 模糊：拉伸 + 模糊——呈现同 stretch，尺寸变化期间三层整体模糊（CSS filter 遮盖布局重排细节），尺寸稳定 settleDelay（默认 250ms）后平滑恢复清晰
- **三层包装壳**：特效宿主（ResizeEffectViewport）挂在视口根的三层结构（Content/Edge/Corner）外面，三层整体参与特效，互不错位；页面视口由 CellRoot 挂载，浮动视口由 FloatingLayer 挂载
- **投影 + 实时追赶**（stretch/blur 共用）：
  - 尺寸变化瞬间：进入投影，冻结当前布局为基准（`_frozenViewportSize` 锁定三层 + 同步 reflow + DOM 直写），包装层 transform scale 实时投影到新尺寸（GPU 合成，不触发逐帧 reflow）
  - 追赶（无防抖）：下一帧（rAF）以最新真实尺寸同步 reflow，reflow 就绪立即交接（解除冻结 → scale 还原 1），无中间帧；基准随追赶同步更新，持续 resize 时投影与追赶逐帧交替
  - freezeZoom 与上述唯一差异：追赶经 setTimeout(settleDelay) 防抖，投影期不触发 reflow，适合 reflow 超过帧预算的复杂布局；布局轻量时 stretch 即可实时
- **触发范围**：仅视口根生效（页面窗口 resize、浮动窗口拖拽缩放）；子 Box 不重复挂载
- **注入**：经 ThemeProvider 注入，视口根特效壳（ResizeEffectViewport）读取当前主题的 resize 特效描述并包裹三层；主题切换触发特效实例重建，布局立即恢复

### 主题包

一个主题包包含完整的静态资源与动态属性定义（含参数型与合成型特效描述）。

- 支持多主题并存（如 light/dark）
- 主题包可组合：基础主题 + 扩展主题，扩展主题覆盖或补充基础主题
- 主题切换通知所有订阅方重新呈现，包括触发特效实例的重建

## i18n 系统

i18n 提供按语言组织的文本资源。

### 语言包

- 按语言组织文本资源，用 key 标识
- 支持变量插值
- 支持语言切换，切换时通知订阅方重新呈现

### 扩展维度

预留以下扩展空间，后续按需启用：
- 数字、日期、货币格式化
- 复数与性别规则
- 文本方向（LTR/RTL）

## 注入与响应机制

主题与 i18n 通过统一的注入机制接入 Cell/Box，按资源类型分两种形态：

**值注入**（静态资源与参数型动态属性）：
- 渲染环境持有当前 Theme 与 I18n 实例
- Cell 内部组件通过约定接口获取 token 的当前值与 i18n 文本的当前译文
- 资源切换时，系统广播变更，订阅相关资源的组件重新呈现

**特效注入**（合成型特效）：
- Cell 声明特效需求（如需要玻璃折射背景），由主题系统匹配特效描述
- 特效渲染器据此创建特效实例，挂载到合成表面，与目标 Cell 关联
- 特效实例的渲染独立于 React DOM，由合成层自行调度
- 主题切换若改变特效描述，触发特效实例重建

注入是单向的：主题/i18n 流向 Cell，Cell 不反向修改主题或语言包（语言与主题的切换由上层控制）。

## 解耦边界

- Cell/Box 不依赖任何具体主题包或语言包
- 主题包与语言包不依赖任何具体 Cell 类型
- 特效渲染器不依赖具体 Cell 类型，仅消费特效描述与输入源
- 唯一的耦合是资源标识约定（token 命名空间、i18n key 命名空间、特效描述协议）
- 资源标识由 Cell 类型作者在定义时声明，主题包与语言包作者据此提供对应资源

## 演进策略

本文档为架构骨架，刻意保持简明，后续将根据补充需求逐步细化并调整架构。预期演进方向：

- 静态资源与动态属性的具体分类与命名规范
- 主题包的组织、加载与组合方式
- 参数型动态属性的描述能力边界与降级策略
- 合成型特效的描述协议、输入源契约与渲染时序规范
- 合成表面的层级管理、共享策略与资源回收
- i18n 的完整能力清单与格式化规则
- 注入机制的具体形态与性能策略
- 资源标识的命名空间约定与冲突处理

架构设计以确保上述演进可在不破坏 Cell/Box 既有定义的前提下进行为目标。
